# MCP and Atlas

Who should read this: anyone wiring Cursor/Claude Desktop to this repo, or comparing the local 12 tools to Industrial MCP and Atlas AI.

## MCP primer

The [Model Context Protocol](https://modelcontextprotocol.io) lets an AI client discover tools and resources over a standard transport. This repo's server speaks **stdio JSON-RPC**: stdout is the protocol; **stderr** is for logs so a stray `console.log` cannot corrupt the stream. `npm run mcp` runs `server/mcp/index.ts` (`StdioServerTransport`). Point a client at `mcp.json.example` (`npx tsx server/mcp/index.ts`, `cwd` = repo root). Do not leave it running after a demo.

On CDF, desktop agents should use [Industrial MCP](https://docs.cognite.com/cdf/build/industrial_mcp) instead of this process. Atlas AI's query / time-series / document tools are the same families ([Agent tools library](https://docs.cognite.com/cdf/atlas_ai/references/atlas_ai_agent_tools)).

## Local server

`createMcpServer` in `server/mcp/server.ts`. Name `pharmaops-copilot`, version `0.1.0`. `batchId` schema: letters/digits/hyphens, max 32.

Resource `pharmaops://agent/guardrails` (register name `agent-guardrails`): markdown of `AGENT_IDENTITY`, `UNIVERSAL_RULES`, `HUMAN_REVIEW_DISCLAIMER`. Clients should read it before `triage_batch`.

Tool count is pinned in `server/mcp/server.test.ts` (12 names).

| Tool | Input (zod) | Output shape |
|------|-------------|--------------|
| `list_batches` | none | `{ batches: [{ id, name, status, currentPhase, plannedStart, actualStart, deviationId }] }` |
| `get_batch_summary` | `batchId` | `{ batch, deviation, relatedEquipment }` |
| `query_events` | `batchId`, optional `start`/`end` ISO | `{ events }` |
| `get_anomaly_windows` | `batchId` | `{ anomalies }` |
| `get_work_orders` | `batchId` | `{ workOrders }` |
| `get_operator_notes` | `batchId` | `{ operatorNotes }` |
| `query_time_series_stats` | `batchId`, optional `signalIds` | `{ stats }` |
| `query_time_series_datapoints` | `batchId`, `signalId`, optional `maxPoints` 10–2000 (default 120) | `{ signalId, batchId, totalPoints, step, points }` downsampled |
| `ask_documents` | `query` 1–500 chars, optional `batchId`, `topK` 1–20 | `{ query, hits: [{ sectionId, documentTitle, title, score, content }] }` |
| `assess_data_quality` | `batchId` | `{ flags }` |
| `build_evidence_packet` | `batchId`, `question` 1–2000 | Full `EvidencePacket` JSON |
| `triage_batch` | `batchId`, `question` 1–2000 | Full `CopilotResponse` (same as HTTP copilot) |

Unknown batch → `isError` text "No batch found… Use list_batches". `triage_batch` calls `runCopilot` (LLM allowed if a key is in the MCP `env`). HTTP evals still force deterministic.

## Mapping to Industrial MCP / Atlas tools

| Local | Family on CDF | Notes |
|-------|---------------|-------|
| `list_batches`, `get_batch_summary`, `query_events`, `get_work_orders`, `get_operator_notes`, `get_anomaly_windows`, `assess_data_quality` | Atlas / Industrial MCP **`query`** | Graph/instance lookup. Atlas YAML names the tool `query_knowledge_graph` with `type: query` ([agent YAML tools](https://docs.cognite.com/dev/sdks/cognite-cli/agent-yaml)). |
| `query_time_series_stats`, `query_time_series_datapoints` | **`queryTimeSeriesDatapoints`** | Stats are a local convenience over the same series. |
| `ask_documents` | **`askDocument`** | Local hybrid index, not a live CDF document index. |
| `build_evidence_packet`, `triage_batch` | Composed | Not Atlas built-in types. On CDF the agent composes `query` + TS + `askDocument` per the skill. |

Do not call the Query tool `queryKnowledgeGraph` as a type — that name is deprecated in older copy. Type is `query`.

## Agents-as-code export

`npm run export:atlas` → `scripts/export-atlas-agent.ts`.

Inputs: `AGENT_IDENTITY` / `UNIVERSAL_RULES` / `HUMAN_REVIEW_DISCLAIMER` from `guardrails.ts`; `evals/eval_cases.json`; `buildEvidencePacket` for faithfulness ground truth.

Outputs (five files, each prefixed `# GENERATED by scripts/export-atlas-agent.ts — edit server/agent/guardrails.ts or evals/eval_cases.json instead.`):

- `cdf/modules/pharmaops_deviation/agents/pharmaops_triage.Agent.yaml`
- `cdf/modules/pharmaops_deviation/agents/pharmaops_deviation_triage.Skill.yaml`
- `cdf/modules/pharmaops_deviation/agents/pharmaops_deviation_triage.Skill.md`
- `cdf/agents/pharmaops-triage/pharmaops-triage.agent.yaml` (CLI twin)
- `cdf/agents/pharmaops-triage/eval/eval.yaml`

Do not hand-edit them. `yamlDump` uses `lineWidth: -1`, `noRefs: true`, `quotingType: '"'` so multi-line instructions stay literal blocks (`|-`) and CI diffs stay stable.

Formats: [Agent definition YAML](https://docs.cognite.com/dev/sdks/cognite-cli/agent-yaml), [Agent evaluation cases](https://docs.cognite.com/dev/sdks/cognite-cli/agents-eval), Toolkit [resource library — agent skills](https://docs.cognite.com/cdf/deploy/cdf_toolkit/references/resource_library#agent-skills).

CLI workflow (not run in this repo): scaffold/push/eval/publish per [Building Atlas AI agents with the Cognite CLI](https://docs.cognite.com/dev/sdks/cognite-cli/agents) (`@cognite/cli` 1.10.0+).

## Skill design

One skill: deviation triage. Atlas docs recommend a skill per distinct workflow ([Configuring skills](https://docs.cognite.com/cdf/atlas_ai/guides/atlas_ai_agent_configure_skills)); this prototype has one workflow.

- **Frontmatter** (`Skill.md`): `name`, `description` — identity the agent uses to decide *when* to load the skill.
- **Body**: when to use; ISA-88/95 + Records + `PharmaDeviation` vocabulary; tool sequencing (query batch → events/WOs → time series → documents); boundaries (no create/update, no release).

Agent `instructions` stay universal (identity, rules, output shape, disclaimer). Workflow-specific sequencing stays in the skill so it loads on demand.
